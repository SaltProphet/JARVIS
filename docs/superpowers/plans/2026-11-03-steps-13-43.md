# JARVIS Steps 13-43 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a truthful, reversible Windows installer for JARVIS steps 13-43, with every automated step executable and every owner-only check explicitly gated.

**Architecture:** Keep `installer/install.ps1` as the ordered orchestrator and move deterministic behavior into focused PowerShell modules and Python stdlib services. The dashboard owns runtime APIs and static UI; external integrations are opt-in and persist only redacted status. Each step gets a substantive pre-check, action, post-check, dry-run path, backup/undo behavior, and automated tests before its milestone gate advances.

**Tech Stack:** Windows PowerShell 5.1, Python 3.12 stdlib, SQLite, plain HTML/CSS/JavaScript, Windows Task Scheduler, Pester, `unittest`.

**Spec:** `docs/PLAN.md` and `jarvis-installer-findings.md`

## Global Constraints

- Bind dashboard, voice, and Home Assistant services to loopback only.
- Never print, log, commit, or return secret values.
- `-DryRun` performs no writes, network calls, process starts, task changes, firewall changes, or agent turns.
- Back up every changed Hermes file and append a reverse-order undo action before mutation.
- Use PowerShell 5.1-compatible syntax and Python standard library for the dashboard server.
- Optional integrations have durable `skipped`, `pending-owner`, `passed`, or `failed` state.
- Never mark phone, hearing, OAuth, or Telegram-owner acceptance checks as automatically passed.
- Do not advance progress when a required post-check fails.

## Review Focus

- Missing, locked, malformed, or changing SQLite/JSON sources must yield truthful unavailable states without server failure.
- Paths from HTTP requests must reject traversal, absolute paths, drive paths, UNC paths, and unsupported extensions.
- Concurrent HTTP writes must use locks and atomic same-directory replacements.
- External services must distinguish skipped, unavailable, unauthorized, rate-limited, and failed states without leaking credentials.
- Installer resume, skip, retry, dry-run, backup, and undo behavior must remain deterministic across every step.
